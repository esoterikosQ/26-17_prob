전 문장을 원래 순서·중복 횟수대로 포함한다. dev의 선택/확인 분할을 test에 다시 적용하지 않는다. Union은 독립적인 세 번째 반복 실험이 아니다. Native 출처는 전체 외에 공백 정규화한 정답문이 Native **train 정답에 없는** 부분도 따로 보고한다(별도 학습 Native 모델이 아님). EC 2벌식 dev 5k나 레거시 KoBART를 새 시험 주표에 섞지 않는다. 과거 BART 프로젝트의 시험 집계가 이미 알려졌으므로 ‘누구도 본 적 없는 시험’이 아니라 **현재 HNC 비교의 일회성 시험**이다.

- **후보·채점:** §6.2의 개발 조건 그대로. H는 학습자 자모·형태소 채널, 어휘 최소 빈도 5, 형태소 후보 30, 빔/최종 폭 8, 보간 LM `.8:.2`. 추가 어휘·과잉 어절 경로는 끈다. 1행은 5행과 동일한 H8의 `G + .3P`만, 2행은 형태소 경로 끔, 3행은 단위 동일 전송·자모 편집과 분할/병합 끔. 4–8은 기존 표의 가중치, H8의 동점은 보관 순서. 운용 B(`.5G + 인과 LM − 채널비용`)는 별도 대조다.
- **강한 신경 기준선:** `gec2` 개별 seed 0, Learner epoch 9 / Lang8 epoch 3 / Union epoch 8. 9행은 각 모델로 **시험 원문만** 주어 생성한 빔 4 1위다. 과거 시험 출력을 읽어 비교하거나 대체하지 않는다. S8은 이번 9행 출력을 포함하고 빔 8의 서로 다른 표층을 최대 8개까지 채운다. BOS/EOS·패딩·마스크·길이 정렬 배치 64·생성 길이 `min(512, 2×배치 최장 입력 + 10)`은 [고정 생성 방식](../scripts/c_strong_generate.py)을 따른다. 구별되는 표층은 공백 정규화 후 문장 안에서만 합친다. 10/11 및 S8 대조는 동일 외부 채널, `.5G + 인과 LM − 채널비용 + λ₄ log P_s2s(y|x)`이며 λ₄는 각각 0/.5/.5. H 전용 후보도 EOS까지 같은 teacher forcing, 점수 동점은 표층 사전순으로 결정한다.
- **질문별 대응 비교:** 주 F0.5 차이 11−9 외에 5−1(고정 후보의 채널 점수), 4−2/4−3(후보 생성도 포함), 5−4·6−8a·7−8b(PCFG), 6−5/7−5(신경 LM), 11−10(조건부 점수), 11−S8(고정 채점기에서 H 후보 추가)를 보조로 보고한다. 유리한 대조만 고르거나 이 차이들을 합산하지 않는다.
- **주 지표:** 동일 공식 어절 M²(가중치 β=.5, 최대 연속 무편집 어절 2, 원래 단일 주석). 문장 간 편집 수를 합쳐 `P=TP/제안`, `R=TP/정답`, `F0.5=5TP/(4×제안+정답)`과 세 원수를 제시한다. CSV 비율은 0–1, 논문 표는 ×100. 신뢰구간은 같은 정규화 정답문을 한 블록으로 묶고 두 시스템에 같은 블록을 복원 추출해 micro 차이를 다시 계산한다([기존 구현](../scripts/c_eval.py), 2,000회, seed 261125, 2.5/97.5 백분위). 구간이 0을 포함하면 방향을 확정하지 않는다. 보조 비교는 탐색적이며 다중 유의성 주장을 하지 않는다.
- **오류유형과 GLEU:** 공식 M² TP의 참조 유형별 재현율은 `일치한 해당 참조 편집 / 해당 참조 편집 전부`다. *편집 단위* 유형별 P/R/F0.5는 KAGAS로 `x→예측문`에도 유형을 붙여 계산한다. 같은 문장·어절 범위·허용 교정 표층·유형이 일치하는 일대일 최대 매칭 수를 `TP_t`, 양측 해당 유형 편집 수를 각각 제안/정답 분모로 한다(noop 제외). 유형이 다른 예측도 분모에 남기며 빈 분모는 NA다. 이 별도 정렬의 합이 공식 M²와 같다고 가정하지 않는다. 과거의 ‘그 유형을 포함한 **문장** 부분집합 F’와도 구별한다. 보조 GLEU는 원문·참조·같은 예측의 공백 토큰, 단일 참조, 4-gram, BART 재현의 `metric.gleumodule.run_gleu`(`26-13_PHDQ_BART` 커밋 `94159a1da6819733b122d037fa717da62c0a9016`) ×100. 보조 도구 실패나 누락은 공개하고 전체인 것처럼 일부 문장만 채점하지 않는다.

## 2. 맹검 설명력: 정답표를 열기 전에 고정할 것

모집단은 **레거시 Learner KoBART 원래 1위**의 dev 확인 변경 구간 3,483개. M² 정오와 관계없이 seed 261125로 뽑힌 구간 100개(`C4-001`–`C4-100`)를 그대로 쓴다. 판정 단위는 문장 전체가 아니라 표시된 `x→제안 y` 한 구간이다. 평가 대상은 실제 작성자의 인지적 원인이 아니라 **원문 현상에 대해 사람이 부여한 유형과 모델 설명의 일치**다.

1. **봉인:** 검수자는 모델의 유형·확률·정답·대조 키를 보지 않는다. 사용자가 완료를 알린 뒤 작성본을 새 경로로 복사해 SHA-256을 남긴다. 먼저 원래 빈 양식과 ID·원문·제안·구간을 대조하고 허용된 답만 검증한다. 중복·누락 ID, 바뀐 구간, 분류할 수 없는 자유기입은 키를 열기 전에 중단한다. 원본은 덮어쓰지 않고, 빈 답은 추정하지 않는다. 검증된 100개 ID로만 보관 키를 결합한다.
2. **교정 타당성:** `타당 / 둘 다 허용 / 부적절 / 판단 어려움 / 미응답` 각각 **100개 전체**를 분모로 n/N을 보고한다. 분명한 판정(`타당+둘 다 허용+부적절`) 안의 엄격 타당률은 `타당/N`, 허용 포함 비율은 `(타당+둘 다 허용)/N`을 별도 표시한다. 허용 변이를 맞힌 문법 오류로 합치지 않는다.
3. **주 설명 일치율:** 사람이 구체적인 유형(아래 8개)을 지정한 **모든 구간**이 분모다. 교정이 부적절하거나 M² FP여도 포함한다. `원문 오류 없음 / 판단 어려움 / 미응답`은 별도 행과 수로 남긴다. 모델은 저장된 원래 MAP 유형을 아래 가족으로 묶는다. `미분류`나 `형태소 세부 미지정`도 분모에서 빼지 않고 불일치로 센다. 분자=양쪽 가족이 같은 수. 전체 교차표(사람 행, 모델 열), 타당성별 n, 그리고 `교정=타당`이면서 구체 유형인 경우의 보조 일치율을 구분한다.

| 사람 유형 | 모델 설명과 대응 |
|---|---|
| 철자·타자 / 띄어쓰기 | `JAMO` / `WS` |
| 조사 / 어미 | `PARTICLE`, `PARTICLE_INS/DEL` / `ENDING`, `ENDING_INS/DEL`. 대치·누락·과잉의 **방향**은 주 일치 조건이 아니다. |
| 어휘 / 통용 변이 | `LEXICAL` / `VARIANT` |
| 문장부호 / 복합·기타 | 문장부호 전용 출력은 현 모형에 없음 / `MIXED`만 대응 |

`MORPH_INS/DEL`은 자동으로 어휘나 복합에 넣지 않고 세부 미지정, `UNCLASSIFIED`는 미분류다. 둘 다 ‘원문 오류 없음’이나 ‘판단 어려움’을 맞혔다고 하지 않는다. **미분류 MAP 비율과 관측 경로 없음(`backoff_only`) 비율**은 각각 100개 전체에 대해 따로 보고한다. KAGAS 유형 일치·공식 교정 TP는 독립 사람 판정의 대용이 아니다.

4. **설명 신뢰도(탐색):** 구체적인 사람 유형과 구체적인 모델 설명이 모두 있는 경우만 대상이다. 저장된 MAP의 가족은 바꾸지 않고, 그 가족에 속하는 원래 사후확률 합(반올림된 전체 합으로 정규화)을 신뢰도로 쓴다. 고정 구간 `[0,.5)`, `[.5,.8)`, `[.8,1]`마다 n·평균 신뢰도·관측 일치율을 보고한다. 대상 ≥50개이고 비어 있지 않은 구간 ≥2개에 각각 ≥10개가 있을 때만 `ECE=Σ(n_b/N)|일치율_b−평균신뢰도_b|`, 아니면 NA와 이유를 낸다. 모든 비율은 분모 0이면 NA. 사후확률을 교정 타당 확률로 해석하거나 이 표본으로 보정기를 학습하지 않는다.

이 100개의 결과를 강한 `gec2` C, 독립 test 전체 또는 사람 간 합의도로 일반화하지 않는다. 독립 시험에서 C의 자동 설명은 9행의 변경과 11행의 변경 **각각 전수**에 대해 구간 수·미분류·백오프만 보고하고, 사람 설명 점수와 분리한다.

완료 통보 **후** itcerdo의 비공개 작업 경로에서만 [맹검 집계기](../scripts/score_blind_review.py)를 쓴다: `python scripts/score_blind_review.py --review-complete --template <보관된_빈_양식> --form <보존한_작성본_사본> --key <보관_키> --out <새_집계_JSON>`. 빈 양식·키 지문은 원래 보관 목록에 고정돼 있다. 모든 답안과 원래 구간의 검증이 끝나기 전에는 키를 읽지 않으며 기존 출력 파일을 덮어쓰지 않는다.

## 3. 실행 게이트와 증거 보존

- 모델 자원은 [final_v1.sha256](./final_v1.sha256)으로 고정한다. itcerdo 프로젝트 루트에서 `sha256sum --strict -c evaluation/final_v1.sha256` 후, 세 `restore/<domain>.sha256` 목록을 **각 모델 디렉토리 안에서** 검사한다. HF는 목록에 적힌 스냅샷에서 오프라인 로드. 개발 환경은 Kiwi 0.25.1(모델 0.25.0), KenLM 0.3.0, Pynini 2.1.7, torch 2.11.0+cu128, transformers 5.24.1, tokenizers 0.23.3이다.
- **PCFG 준비 조건:** `phdq_pcfg2` K4-5 `pcfg_best.pkl`(v=3, h=1, 어절 경계·기능표지 유지, 품사별 UNK), 채점기 소스 기준 `0ca1883048dd33ab1509989a8aa8d4909bcf98e2`. HNC 프로젝트 안에 신뢰할 수 있는 복사본을 준비하고 파일 지문을 기록한다. 이름만으로 승인하지 않는다. 동결한 Learner H8 34,110개의 `parsed` 일치 및 `pcfg` 점수 오차 ≤`1e-8`을 **dev에서** 확인하기 전에는 시험을 열지 않는다. 현재 있는 것은 개발 결과 캐시이지 새 문장을 채점할 문법 파일이 아니다.
- **시험 실행 전:** 기존 dev 전용 스크립트의 경로를 시험 자료로 바꿔 덮어쓰지 않는다. 전용 실행기가 원문만으로 후보를 생성·선택하고, §6.2 개발 표 전체와 세 모델의 보관 빔 4 출력을 재현하는지 확인한다. KAGAS·GLEU도 개발 입력으로 먼저 검증한다. 차이가 나면 원인을 기록하고 중단한다. 프로토콜·실행기 커밋, 자원 지문, 지표·분모가 고정되고 사용자가 최종 실행을 승인한 후에만 별도 비공개 `outputs/` 디렉토리에서 시작한다. 검수 완료 여부와 시험 실행 승인은 별개의 게이트다.
- **한 번의 개봉:** 공식 원자료의 순서·규모·문장 ID를 검증한다. 동일 문장을 임의로 제거하지 않는다. 예측에 입력 가능한 것은 `x`와 고정 모델뿐이다. 모든 시스템의 예측·후보 출처·설정·해시를 먼저 봉인하고, 그 뒤 참조/M²를 결합해 일괄 채점한다. 순서/주석 수 불일치, 비유한 점수, 누락 출력은 중단 사유다. 단일 주석 충분통계와 공식 CLI P/R/F 차이 허용치는 각 `0.000051`(0–1)이다. 기술 실패는 기록하고 동일 설정/같은 봉인 예측으로만 재개한다. 결과를 보고 재튜닝·부분집합 변경·최고 시드 선택을 하면 새 탐색이지 이 시험의 재실행이 아니다.
- **보관:** 원문·키·가중치는 공개하지 않는다. itcerdo에서 집계한 뒤 T31로 증거를 옮겨 SHA-256을 검증한다. 성능과 설명력 모두 실측 전에는 미측정으로 둔다. 이후 Learner 한계 원인 분석은 [계획의 마지막 §5](../plan.md)에 둔다.
